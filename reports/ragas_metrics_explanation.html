¿Qué es RAGAS?

RAGAS (Retrieval Augmented Generation Assessment) es un framework de evaluación automática para sistemas RAG. Permite medir la calidad de las respuestas generadas sin necesidad de evaluadores humanos para cada pregunta, usando un LLM juez externo que actúa como árbitro.


Un sistema RAG tiene dos componentes que pueden fallar independientemente:

  • Retrieval (recuperación): ¿Se recuperaron los chunks correctos? → medido por Context Precision y Context Recall
  • Generation (generación): ¿La respuesta es fiel y relevante? → medido por Faithfulness y Answer Relevancy

1. Faithfulness (Fidelidad)

¿La respuesta está respaldada por los contextos recuperados?

¿Qué mide?

Faithfulness detecta alucinaciones: situaciones donde el LLM genera información que no está presente ni puede inferirse de los chunks recuperados. Un score de 1.0 significa que cada afirmación de la respuesta tiene soporte en el contexto; 0.0 significa que todo fue inventado.

Modelos juez utilizados

RolModeloJustificación
LLM Juez gpt-4o-mini (temperatura=0) Requiere generar JSON estructurado con veredictos. Los modelos locales (gpt-oss:20b, llama3.2) producían NaN al fallar en el formato.
Embeddings text-embedding-3-small (OpenAI) Requerido internamente por RAGAS para este módulo.
⚠️ Nota: Se intentó primero con modelos Ollama (gpt-oss:20b). El algoritmo requiere que el LLM genere un JSON estructurado con campos statement, reason y verdict. Los modelos locales fallaban consistentemente en seguir este formato estricto, resultando en NaN. Se migró a gpt-4o-mini que tiene mayor adhesión a instrucciones de formato.

Algoritmo paso a paso

  • 1
    Descomposición en afirmaciones atómicas

    El LLM juez recibe la generated_answer y la divide en afirmaciones simples e independientes, cada una verificable por separado.

    Prompt interno RAGAS — Paso 1
    Given the following statement, break it down into individual factual claims.
    Each claim should be a single, verifiable statement.

    Statement: "El Semáforo tiene 50 indicadores en 8 dimensiones.
    La dimensión de Vivienda incluye acceso a agua potable."

    Output:
    ["El Semáforo tiene 50 indicadores",
     "Los indicadores están distribuidos en 8 dimensiones",
     "La dimensión de Vivienda incluye acceso a agua potable"]
  • 2
    Verificación de cada afirmación contra el contexto

    Por cada afirmación, el LLM verifica si puede ser inferida directamente de los retrieved_contexts. Devuelve un JSON con veredicto 1 (soportado) o 0 (no soportado).

    Prompt interno RAGAS — Paso 2
    Consider the given context and following statements, then determine
    whether they are supported by the information present in the context.

    Context: "...texto de los chunks recuperados..."
    Statement: "El Semáforo tiene 50 indicadores"

    Output JSON:
    {"statement": "El Semáforo tiene 50 indicadores",
     "reason": "The context explicitly mentions 50 indicators",
     "verdict": 1}

    {"statement": "La dimensión tiene 12 sub-indicadores",
     "reason": "This specific number is not mentioned in context",
     "verdict": 0}
  • 3
    Cálculo del score final

    Se divide el número de afirmaciones soportadas entre el total:

    Faithfulness = Σ(verdict = 1) / total_afirmaciones 
    # Implementación en el código del proyecto
df = result.to_pandas()
faithfulness = df["faithfulness"].iloc[i]  # float 0.0 – 1.0

# Guardado en PostgreSQL
UPDATE eval_scores
   SET faithfulness = 0.833
 WHERE eval_run_id = 1234

2. Answer Relevancy (Relevancia de la Respuesta)

¿La respuesta generada responde la pregunta del usuario?

¿Qué mide?

Answer Relevancy detecta respuestas vagas, incompletas o fuera de tema. No evalúa si la información es correcta, sino si la respuesta está orientada a contestar la pregunta específica. Una respuesta correcta pero sobre otro tema tendría score bajo.

Modelos juez utilizados

RolModeloJustificación
LLM Juez gpt-oss:20b (Ollama, temperatura=0) Genera preguntas sintéticas a partir de la respuesta. Los modelos locales funcionan bien para esta tarea de generación libre (no requiere JSON estricto).
Embeddings bge-m3 (Ollama, 1024 dims) Calcula la similitud coseno entre la pregunta original y las preguntas sintéticas.

El ground_truth y los retrieved_contexts no se usan en esta métrica.

Algoritmo paso a paso

  • 1
    Generación de preguntas sintéticas

    El LLM juez recibe la generated_answer y genera N=3 preguntas que esa respuesta podría contestar.

    Prompt interno RAGAS — Paso 1
    Generate a question for the given answer.

    Answer: "El Semáforo de Pobreza evalúa 50 indicadores distribuidos
    en 8 dimensiones como vivienda, salud y educación."

    Pregunta sintética 1: "¿Cuántos indicadores evalúa el Semáforo?"
    Pregunta sintética 2: "¿Qué dimensiones cubre el Semáforo de Pobreza?"
    Pregunta sintética 3: "¿Cómo está organizado el Semáforo de Pobreza?"
  • 2
    Cálculo de embeddings

    Se vectorizan la pregunta original y cada pregunta sintética usando bge-m3:

    embedding_original   = bge-m3.embed("¿Cuáles son los indicadores del semáforo?")
embedding_sintetica1 = bge-m3.embed("¿Cuántos indicadores evalúa el Semáforo?")
embedding_sintetica2 = bge-m3.embed("¿Qué dimensiones cubre el Semáforo?")
embedding_sintetica3 = bge-m3.embed("¿Cómo está organizado el Semáforo?")
  • 3
    Similitud coseno y promedio

    Se calcula la similitud coseno entre la pregunta original y cada sintética, luego se promedia:

    Answer Relevancy = (1/N) × Σ cosine_sim(emb_original, emb_sintética_i)
    📌 Intuición: Si la respuesta fue vaga o fuera de tema, las preguntas sintéticas generadas divergirán de la pregunta original → similitud coseno baja → score bajo. Si la respuesta es directa y específica, las preguntas sintéticas serán similares a la original → score alto.

3. Context Precision (Precisión del Contexto)

¿Los chunks más relevantes aparecen en las posiciones más altas del ranking?

¿Qué mide?

Context Precision evalúa la calidad del ranking del retriever. No solo si se recuperaron chunks relevantes, sino si esos chunks relevantes están en las primeras posiciones. Un retriever que coloca chunks irrelevantes al inicio (aunque los relevantes estén en la lista) tendrá score bajo.

📌 ¿Por qué importa el ranking? Los LLMs tienden a prestar más atención al inicio del contexto (fenómeno "lost in the middle"). Si los chunks irrelevantes aparecen primero, el LLM podría ignorar los relevantes.

Modelos juez utilizados

RolModeloJustificación
LLM Juez gpt-4o-mini (OpenAI, temperatura=0) Determina si cada chunk es relevante comparándolo con el ground truth. Requiere razonamiento preciso → se usó OpenAI.
Embeddings text-embedding-3-small (OpenAI) Requerido internamente por RAGAS.

Algoritmo paso a paso

  • 1
    Clasificación de relevancia por posición

    Para cada chunk recuperado en posición k (k=1,2,3,...), el LLM juez determina si ese chunk es relevante para responder la pregunta, usando el ground_truth como referencia:

    Prompt interno RAGAS
    Given the question and reference answer, determine if the following
    context is relevant and useful to answer the question.

    Question: "¿Cuáles son los indicadores del semáforo?"
    Reference: "50 indicadores en 8 dimensiones..."
    Context [posición 1]: "...texto del chunk 1..."

    Output: {"relevance": 1} ← relevante
    Output: {"relevance": 0} ← no relevante
  • 2
    Cálculo de precisión ponderada por rango

    Se aplica una fórmula que penaliza los chunks relevantes en posiciones bajas:

    Context Precision@K = Σk=1..K( Precision@k × relk ) / total_relevantes

    donde: Precision@k = (chunks relevantes en posiciones 1..k) / k 
    # Ejemplo con 4 chunks recuperados:
# Posición 1: relevante (rel=1)  → Precision@1 = 1/1 = 1.00
# Posición 2: irrelevante (rel=0) → no contribuye
# Posición 3: relevante (rel=1)  → Precision@3 = 2/3 = 0.67
# Posición 4: irrelevante (rel=0) → no contribuye

# Total relevantes = 2
# Context Precision = (1.00 + 0.67) / 2 = 0.833

# Si los mismos chunks estuvieran en orden 2,4,1,3:
# Posición 1: irrelevante → no cuenta
# Posición 2: relevante  → Precision@2 = 1/2 = 0.50
# Posición 3: irrelevante → no cuenta
# Posición 4: relevante  → Precision@4 = 2/4 = 0.50
# Context Precision = (0.50 + 0.50) / 2 = 0.50  ← peor ranking = peor score

0.50–0.79Bueno

0.30–0.49Moderado

< 0.30Deficiente

4. Context Recall (Cobertura del Contexto)

¿El contexto recuperado contiene toda la información necesaria para responder?

¿Qué mide?

Context Recall evalúa si el retriever encontró suficiente información. Si el ground truth dice que la respuesta correcta requiere información de 5 oraciones y el retriever solo recuperó chunks que cubren 3, el recall será 3/5 = 0.60. Un recall bajo significa que el LLM no tenía toda la información disponible para responder correctamente.

Modelos juez utilizados

RolModeloJustificación
LLM Juez gpt-oss:20b (Ollama, temperatura=0) Verifica qué oraciones del ground truth pueden atribuirse al contexto. Funciona bien con modelos locales para esta tarea de matching semántico.
Embeddings bge-m3 (Ollama) Usado internamente por RAGAS en algunas variantes de la métrica.

La generated_answer no se usa en Context Recall — es una métrica pura del retriever, no del generador.

Algoritmo paso a paso

  • 1
    Descomposición del ground truth en oraciones

    El LLM juez divide la respuesta de referencia en oraciones individuales:

    Prompt interno RAGAS — Paso 1
    Break down the following reference answer into individual sentences:

    Reference: "El Semáforo evalúa 50 indicadores. Están distribuidos en
    8 dimensiones. La dimensión de vivienda incluye agua potable
    y saneamiento. Las familias se autoaplican la encuesta."

    Oraciones: ["El Semáforo evalúa 50 indicadores",
             "Están distribuidos en 8 dimensiones",
             "La dimensión de vivienda incluye agua potable y saneamiento",
             "Las familias se autoaplican la encuesta"]
  • 2
    Verificación de cobertura por el contexto

    Por cada oración del ground truth, el LLM verifica si puede ser atribuida a algún chunk recuperado:

    Prompt interno RAGAS — Paso 2
    For each sentence in the reference, determine if it is attributable
    to the provided context.

    Context: "...textos de los chunks recuperados..."

    Sentence 1: "El Semáforo evalúa 50 indicadores" → attributed: 1
    Sentence 2: "Están distribuidos en 8 dimensiones" → attributed: 1
    Sentence 3: "Incluye agua potable y saneamiento" → attributed: 1
    Sentence 4: "Las familias se autoaplican la encuesta" → attributed: 0
  • 3
    Cálculo del score final
    Context Recall = oraciones_atribuidas_al_contexto / total_oraciones_ground_truth 
    # Ejemplo:
# Ground truth: 4 oraciones
# Cubiertas por el contexto: 3
# Context Recall = 3/4 = 0.75

UPDATE eval_scores
   SET context_recall = 0.75
 WHERE eval_run_id = 1234

llama3.2:latest + nomic-embed-text + chunk large

Datos de entrada

CampoValor
Pregunta¿Qué es el Banco de Soluciones?
Respuesta generada "El Banco de Soluciones es la asistente conversacional que te ayudará a encontrar soluciones y respuestas a tus preguntas. Estoy aquí para proporcionarte información y apoyo en una variedad de temas, desde educación y desarrollo económico hasta tecnología e innovación. Mi objetivo es brindarte información precisa y útil, basada en fuentes confiables y actualizadas."
Ground TruthEl Banco de Soluciones es una plataforma colaborativa que reúne herramientas, servicios y recursos prácticos para acompañar a las personas, familias y comunidades en la mejora de sus indicadores del Semáforo...

Scores obtenidos

0.100Faithfulness

0.913Answer Relevancy
Responde la pregunta
0.000Context Precision
Chunks erróneos al inicio
0.000Context Recall

Interpretación — ¿Qué salió mal?

  • Faithfulness = 0.100: El LLM confundió "Banco de Soluciones" con el nombre del chatbot (Luz). Las afirmaciones "asistente conversacional", "educación y tecnología e innovación", "fuentes confiables y actualizadas" no estaban en ningún chunk recuperado — fueron inventadas. Solo 1 de ~10 afirmaciones tenía soporte real.
  • Answer Relevancy = 0.913: A pesar de alucinaciones, la respuesta sí intenta responder "¿Qué es el Banco de Soluciones?" → las preguntas sintéticas generadas eran similares a la original. Answer Relevancy no detecta alucinaciones, solo mide si la respuesta está orientada a la pregunta.
  • Context Precision = 0.000 y Context Recall = 0.000: El embedding nomic-embed-text con chunk large recuperó chunks completamente irrelevantes para esta pregunta (posiblemente documentos sobre el manual metodológico en lugar del banco de soluciones).
⚠️ Lección: Este ejemplo demuestra la diferencia entre métricas. Answer Relevancy puede ser alta aunque el contenido sea falso. Por eso es imprescindible usar Faithfulness junto con Answer Relevancy — una respuesta puede parecer relevante pero estar completamente fabricada.

gpt-oss:20b + snowflake-arctic-embed + chunk small

Datos de entrada

CampoValor

Ground TruthNo. Podés usar el Banco de Soluciones tanto si ya sos usuario del Semáforo como si no. Cualquier persona puede explorar Soluciones y recibir orientación a través del chatbot, sin necesidad de estar vinculada a una organización...

0.000Faithfulness
No hay afirmaciones
0.000Answer Relevancy
No respondió nada
0.000Context Precision
Contexto incorrecto
0.000Context Recall

Interpretación — ¿Qué salió mal?

  • Context Precision = 0 y Context Recall = 0: El embedding snowflake-arctic-embed con chunk small recuperó chunks del manual metodológico en lugar del documento del Banco de Soluciones. El retriever falló completamente.
  • Answer Relevancy = 0: El LLM gpt-oss:20b respondió honestamente que no tenía contexto — pero una respuesta "no sé" genera preguntas sintéticas que divergen completamente de la pregunta original → score 0.
  • Faithfulness = 0: Sin afirmaciones verificables en la respuesta, no hay nada que evaluar. RAGAS asigna 0 por defecto.
📌 Conclusión: Este caso muestra que snowflake-arctic-embed con chunk pequeño tiene problemas para recuperar información sobre el Banco de Soluciones. El modelo de embedding es el cuello de botella, no el LLM generador.
